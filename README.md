# dpiprobe

Проверка того, как провайдер вмешивается в трафик: подменяет DNS, режет сайты по имени (SNI) или по адресу, режет QUIC, обрывает соединения с зарубежными хостингами после 16–20 КБ, блокирует Telegram.

Один exe без зависимостей. Запустили — через 3–5 минут получили отчёт с выводами: не просто «не открывается», а *почему* и *что с этим делать*.

## Запуск

1. **Выключите VPN и обход DPI** (zapret, GoodbyeDPI, ByeDPI) — иначе проверяется путь через них, а не провайдер. Утилита сама предупредит, если увидит VPN-интерфейс или запущенный обходчик.
2. Скачайте `dpiprobe.exe` со страницы [Releases](../../releases) и запустите двойным кликом.
3. Отчёт сохранится рядом с exe: `dpiprobe-<дата>-<время>.txt` и `.json`. Окно в конце ждёт Enter.

Из терминала:

```
dpiprobe.exe                                  # всё
dpiprobe.exe -only dns,tls                    # только DNS и сайты
dpiprobe.exe -target 1.2.3.4@www.example.com  # свой сервер: обрыв 16 КБ с нужным SNI и ответ по UDP (QUIC)
dpiprobe.exe -target vpn.example.com:8443     # Hysteria2/TUIC на своём порту: отвечает ли по UDP
dpiprobe.exe -domains youtube.com,x.com       # свои домены вместо стандартного списка
```

Флаги: `-only net,dns,tls,quic,tcp16,tg`, `-target host[:port][@sni],…`, `-domains …`, `-json файл`, `-parallel 8`, `-timeout 8s`, `-sni=false` (не искать белые SNI).

Сборка из исходников: `go build ./cmd/dpiprobe` (Go 1.27+). В релизах есть и готовые файлы для Linux и macOS.

## Можно ли доверять exe

Релизы собирает GitHub Actions ([release.yml](.github/workflows/release.yml)) из открытого кода, на компьютере автора exe не собирается. Каждый файл подписан аттестацией GitHub: она подтверждает, что файл собран этим workflow из конкретного коммита этого репозитория.

```
gh attestation verify dpiprobe.exe --repo sovereignbrains/dpiprobe
```

Без `gh` — сверьте SHA-256 со списком в описании релиза (`Get-FileHash dpiprobe.exe` в PowerShell, `sha256sum` в Linux).

**Не доверять никому, даже GitHub.** Сборка воспроизводимая: из того же тега той же версией Go получается побайтно тот же exe. Соберите сами и сравните хеш с релизным — совпал, значит в релизе ровно этот код. Версия Go — строка `go` в `go.mod` этого тега (для v0.3.0 — 1.27.0); нужной версии Go не будет — `GOTOOLCHAIN` скачает её сам.

PowerShell:

```
git clone https://github.com/sovereignbrains/dpiprobe; cd dpiprobe; git checkout v0.3.0
$env:GOTOOLCHAIN='go1.27.0'; $env:GOOS='windows'; $env:GOARCH='amd64'; $env:CGO_ENABLED='0'
go build -trimpath -ldflags "-s -w -X main.version=0.3.0" -o dpiprobe.exe ./cmd/dpiprobe
Get-FileHash dpiprobe.exe
```

Linux/macOS:

```
git clone https://github.com/sovereignbrains/dpiprobe && cd dpiprobe && git checkout v0.3.0
GOTOOLCHAIN=go1.27.0 GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags "-s -w -X main.version=0.3.0" -o dpiprobe.exe ./cmd/dpiprobe
sha256sum dpiprobe.exe
```

Сторонние экшены в workflow закреплены по хешу коммита, а не по тегу версии: их нельзя тихо подменить, переписав тег.

## Что проверяется

| Раздел | Как | Что в отчёте |
|---|---|---|
| **DNS** | Эталон — ответы нескольких **нефильтрующих** DoH. Затем те же домены через обычный UDP к Google, Cloudflare, OpenDNS, Yandex, MSK-IX, НСДИ и системный резолвер. Запрос `whoami.akamai.net` показывает, кто ответил на самом деле | «ПЕРЕХВАТ» — на ваш запрос к 8.8.8.8 ответил чужой резолвер; «ПОДМЕНА» — ответ не совпал с эталоном ни по адресу, ни по сети /24, ни по ASN; «ВБРОС» — сначала пришёл поддельный ответ, следом настоящий |
| **Зашифрованный DNS** | DoH и DoT 10 провайдеров: доходит ли запрос и врёт ли сервер про запрещённый домен | Какой DNS можно поставить вместо обычного |
| **Сайты** | HTTP на 80-й порт и TLS на 443-й по настоящему адресу (из DoH, а не от системного DNS). Если TLS не прошёл — две перекрёстные пробы: тот же адрес с нейтральным SNI и запрещённое имя на чистом зарубежном адресе | «DPI по SNI», «блок по IP», «режут и то и другое» или «только связка имя+адрес»; заглушка или увод на чужой сайт по HTTP |
| **QUIC** | Настоящий QUIC Initial (RFC 9000/9001) с ClientHello и SNI сайта на UDP 443 — так же, как его шлёт браузер или Hysteria2. Молчание сверяется перекрёстно: тот же адрес с нейтральным SNI и запрещённое имя на зарубежный QUIC-сервер, который отвечает на любое имя. С `-target` — свои серверы на их портах | «DPI по SNI» для QUIC, «адрес не отвечает» (QUIC у сайта нет или UDP закрыт), QUIC за рубеж закрыт целиком — значит, Hysteria2/TUIC не заработают |
| **Обрыв 16–20 КБ** | ~110 адресов крупных хостингов и CDN. Одно TCP-соединение, которое утилита держит сама: данные вверх (заголовки) и вниз (ответы) до 64 КБ. Обрыв проверяется повтором на новом соединении | DETECTED с объёмом, на котором замерло; для таких сетей — **белые SNI**, с которыми обрыва нет |
| **Telegram** | Настоящий запрос MTProto (`req_pq_multi` поверх obfuscated2) к пяти дата-центрам и загрузка с telegram.org | Отвечает ли протокол, а не просто открывается ли порт |

## Чем отличается от dpi-detector

Идея и списки целей — из [dpi-detector](https://github.com/Runnin4ik/dpi-detector) (MIT, см. [NOTICE](NOTICE)); код написан заново. Методика строже в нескольких местах:

| | dpi-detector | dpiprobe |
|---|---|---|
| Обрыв 16–20 КБ | пул соединений httpx: если сервер закрыл keep-alive, клиент молча открывает новое соединение, счёт байт обнуляется — получается ложный «OK» | своё соединение; закрытие сервером — «не определить»; проверка в обе стороны; DETECTED только после повтора |
| Причина недоступности сайта | «TLS DROP» | разделение «по SNI / по IP / по связке» перекрёстными пробами |
| Адрес сайта для проверки | системный DNS, который провайдер может подменить | DoH |
| Эталон DNS | все DoH и DoT, включая фильтрующие (семейные, российские) | только нефильтрующие; сверка адрес → /24 → ASN, чтобы CDN не давали ложных подмен |
| Вброс поддельного DNS-ответа | — | ловится второй ответ на тот же запрос |
| Telegram | TCP-подключение и HTTPS к адресу Telegram | рукопожатие MTProto |
| QUIC / UDP | — | QUIC Initial с SNI, перекрёстные пробы; свои UDP-серверы |
| Установка | Python 3.8+ и зависимости | один exe |

Чего в dpiprobe **нет**, а в dpi-detector есть: IPv6, работа через прокси, Docker, меню и конфиг-файл, раздельные тесты TLS 1.2/1.3, замер скорости отдачи в Telegram.

## Наблюдение

На одном домашнем провайдере (октябрь 2026) запрещённые имена, отправленные на адрес российского сайта, проходили без помех — 27 из 27, тогда как те же имена на зарубежный адрес обрывались. Похоже, SNI проверяется только в трафике за рубеж. Отчёт показывает это отдельной строкой — если у вас так же, напишите в issues.

## Ограничения

- Только IPv4.
- Вывод зависит от времени и сети: блокировки меняются, повторите проверку, если результат выглядит странно.
- Списки целей — снимок из dpi-detector; часть адресов со временем перестаёт отвечать (такие помечаются SYN DROP/REFUSED и в выводы не попадают).
